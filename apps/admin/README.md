# FixinDays Admin Console

Web admin console for the FixinDays platform: provider verification queue,
provider activation/suspension, booking oversight, support tickets, review
moderation, user restriction, platform settings, announcements, and a full
admin audit log.

## Run

```bash
cd apps/admin
flutter pub get
flutter run -d chrome          # web is the primary target
```

Without Firebase configured, the app falls back to **clearly-labelled demo
mode** (in-memory seed data + demo banner). Sign in as
`admin@fixindays.demo` with any password.

## Connect Firebase (real mode)

Follow `FIREBASE_SETUP.md` at the repo root, then:

```bash
cd apps/admin
flutterfire configure          # replaces lib/firebase_options.dart stub
flutter run -d chrome
```

## Authorization model — read this first

Admin rights come **only** from the Firebase Auth custom claim
`admin: true` on the ID token. The console checks the claim with
`user.getIdTokenResult()` after sign-in; users without the claim are signed
straight back out with a "Not authorized" error.

**We never check a Firestore field for admin rights** — any signed-in user
could forge such a field. `firestore.rules` enforces the same rule
server-side (`request.auth.token.admin == true`), so the UI check is just a
friendly gate; the rules are the real enforcement.

Grant the first admin claim with the `setAdminClaim` Cloud Function (only
callable by an existing admin) — bootstrap command in `FIREBASE_SETUP.md`.

## Structure

- `lib/main.dart` — Firebase init (try/catch → demo fallback), providers, theme
- `lib/firebase_options.dart` — generated by `flutterfire configure` (stub until then)
- `lib/src/state/admin_state.dart` — auth + repo selection (`AdminState`)
- `lib/src/data/demo_admin.dart` — in-memory `AdminRepository` (seed data, labelled)
- `lib/src/data/firestore_admin.dart` — real `AdminRepository` on Firestore
- `lib/src/screens/` — login gate + 10 admin screens with loading/empty/error/retry

## Screens

| Screen | Does |
|---|---|
| Dashboard | metric cards: customers, providers, pending apps, active bookings, open tickets, bookings today |
| Applications | pending verification requests; document paths; approve/reject with note (audit-logged) |
| Providers | search; activate/suspend (audit-logged) |
| Bookings | search by ID/customer, status filter chips, detail dialog with items/totals/timeline |
| Tickets | open/in-progress support tickets; status updates (audit-logged) |
| Reviews | hide/unhide reviews (audit-logged) |
| Users | search; restrict/unrestrict (audit-logged) |
| Announcements | publish to `announcements` collection (push delivery needs FCM config) |
| Settings | commission bps, support contacts, cash toggle, response timeout |
| Audit log | every admin action, newest first |
